## 已知问题分析

### 为什么会崩溃？
根据你的描述 "索引完成后立即崩溃"，问题可能是：

1. **在 `indexingFinished` 信号处理中**
   - 调用 `getStats()` 查询数据库
   - SQLite 查询失败导致异常
   - 异常未被正确捕获（虽然我们加了 try-catch）

2. **可能的其他原因**：
   - 数据库连接在多线程环境下不稳定
   - QObject 对象生命周期问题
   - Windows 特定的 Qt 问题

## 最可能的真正原因

我现在怀疑问题是：**QtConcurrent 线程和主线程的对象生命周期冲突**

```cpp
// 后台线程
QtConcurrent::run([this]() {
    // 索引完成
    emit indexingFinished();  // ← 触发信号
});

// 主线程
connect(indexer_, &FileIndexer::indexingFinished, [this]() {
    IndexStats stats = indexer_->getStats();  // ← 在这里崩溃？
});
```

### 可能的问题
1. 后台线程结束但还没完全清理
2. 主线程立即访问数据库
3. SQLite 不喜欢这样
4. 崩溃

### 如果是这个问题的解决方案

需要确保 `indexingFinished` 信号在后台线程真正结束后才发出。

## 下一个修复版本计划

如果日志显示是 `getStats()` 的问题，我会：

### 方案 A：延迟调用
```cpp
connect(indexer_, &FileIndexer::indexingFinished, [this]() {
    // 延迟100ms再调用 getStats()
    QTimer::singleShot(100, [this]() {
        IndexStats stats = indexer_->getStats();
        // ...
    });
});
```

### 方案B：移除 getStats() 调用
```cpp
connect(indexer_, &FileIndexer::indexingFinished, [this]() {
    onLogMessage("Content indexing finished");
    // 不调用 getStats()，避免数据库访问
});
```

### 方案C：使用缓存的统计信息
```cpp
// indexer_ 在完成时更新 stats_
// getStats() 只返回缓存值，不查询数据库
```
